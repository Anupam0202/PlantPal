## Open blockers and decisions

- Pl@ntNet identification is not integrated: its API takes the key in the URL query (forbidden for keys here) and needs a second user key; owner to choose between a server proxy with the owner's key or BYOK through the vault.
- Live provider and Gemini verification require a network-enabled environment and the owner's own Gemini key (`GEMINI_API_KEY=… pnpm eval:live -- --limit 20`). The 124 replay cases are synthetic, not model recordings.
- WCVP native ranges and the WGSRPD level-3 lookup are **not imported yet**: the Kew download and boundary files are not reachable from this sandbox and their licence text needs confirming. Until then the garden region is the ISO country from place search, and native statuses in the seed are drafts.
- Performance follow-up (M12 pass): the lazily loaded data chunk is ~79 kB gzip (Zod classic, Dexie, temporal-polyfill). Options: `zod/mini` for client schemas, and use native `Temporal` where the browser ships it with the polyfill loaded only as a fallback.
- Form inputs are metric (displays follow the units preference). Imperial input fields are planned with the M5 care engine.
- Live provider verification is NOT_RUN: the sandbox blocks every provider host. Steps to verify are in `docs/providers/README.md`.
- Deploying the Worker needs the owner's Cloudflare account and approval (`wrangler login`, `wrangler d1 create plantpal`, set `database_id`, `wrangler deploy`).
- i18n catalogues are bundled with the app shell (initial JS now 150 kB of 170 kB). Next step: load the Hindi and Spanish catalogues only when chosen.
- Catalogue trait values are AI drafts marked `needs_review`; ASPCA toxicity entries and the GRIIS India / Australian WoNS listings were transcribed from search results because the sites could not be fetched. A curator must review them against the live sources before launch.
- Phone horizon scan (DeviceOrientation + camera) needs an offline World Magnetic Model for true north; the manual horizon editor covers the same need meanwhile.
